### rc.4 的两处修复

1. **DeepSeek 内容拒答错误码**：`MALFORMED_RESPONSE` → 新增 **`CONTENT_REFUSED`**。
   当模型以 `stop_reason: "refusal"` 结束时，LLM 错误终止块与 `turn/end` 现在报"提供方拒答"，
   不再误报为"响应格式错误"。改动落在若干错误码表（`dsh-tmux-context/lib/index.js`、
   `dsh-session-persistence-jsonl/lib/worker.cjs` 等），随包带升级指南
   `docs/upgrade-guide/v0.2.2-rc.3/deepseek-refusal-code/`。
2. **`dsh-experimental-liveshare`**：tunnel worker 启动时继承 `ELECTRON_RUN_AS_NODE`
   （Desktop/Electron 载荷下 worker 被单实例锁杀掉）—— Whale 端侧不跑 Electron、liveshare 未启用，**与本端无关**。

## 2. 升级动作

同 `docs/138` §2，只是版本号为 rc.4：

1. `coreVersion` → `0.2.2-rc.4+whale.1`；`AppScope` → 1.1.11 / 1010011；
2. `pack-core` 直接跑会 `npm install → exit=null`（已知坑，见 `docs/138` §4）⇒ 先手动
   `npm install --os=openharmony --cpu=arm64 --ignore-scripts`（node24 的 npm，2 分钟 / 668 包），
   再 `pack-core --skip-install --place-in-app`；
3. 刷新 `contracts.json`（`DSH_NODE_MODULES=<rc.4 树>/node_modules node tools/protocol-contract.mjs --json …`）后跑 `compat-drift`。
