## 七、本次新踩的坑（别再踩）

1. **strip 之后必须重签**：`llvm-strip --strip-unneeded` 只删 debug/symtab/strtab，但会让 `.codesign` 与内容不匹配 ⇒ OHOS 加载器拒绝加载，症状极具误导性（`Error relocating … _ZN4node5StartEiPPc: symbol not found`，看起来像导出符号丢了）。**先 `ohos-selfsign sign` 再进包**（24 线那次也是 stripped-resigned）。
2. **`entry/build` 的旧中间物会把旧 libnode 打进 HAP**：换 `.so` 后若只增量 build，`intermediates/libs/...` 里残留 `libnode.so.137` ⇒ HAP 同时带两份（571 MB）。**换原生库必须清 `entry/build` + `entry/.cxx`**（docs/124 同款教训）。
3. **预编译第三方 .so（sharp/node-pty）的闭包要跟着改**：`collect-libvips.mjs` 会按 `entry/libs` 里实际存在的 libnode 名改写 `DT_NEEDED`；换 Node 版本后必须重跑，否则 `check-native-closure` 报 `libnode.so.137 无法解析`。
4. `bm dump` 的 JSON 里 `versionCode` 有多处（quickfix 段为 0），取顶层或 `applicationInfo.versionCode`；`grep | head` 容易误读成 0。
