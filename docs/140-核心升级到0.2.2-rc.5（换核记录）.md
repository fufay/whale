### 功能性变更（web 搜索默认值）

| 包 | 变化 |
|---|---|
| `dsh-web` | 搜索提供方改为**按模型路由自动选择**：DeepSeek 路由（`deepseek-official` / `deepseek-account`）上的搜索用 `deepseek-official`（legacy Messages 搜索：不按次计费、按 token 计费、会话日志追加 `web/deepseek-search-llm-request`）；其它路由仍用 `deepseek-search-api` |
| `dsh-web-search-deepseek` | Messages 搜索结果解析改进（`web_search_result` 自带 snippet 优先，否则回退 citations） |
| `dsh-tool-web` | `web_search` 把调用方模型请求的路由（`llmProvider`）传给搜索服务 |
| `dsh-base` | `web` 行默认值删掉 `searchProvider: deepseek-search-api`（交给 dsh-web 自动选） |
| `dsh-tool-cordis` / `dsh` | 仅 API catalog 文案 / 升级指南文档 |

> ⚠️ **本版唯一需要真机验证的行为变化**：`web_search`。我们 profile **没有固定 `web.searchProvider`**，
> 升级后走自动选择 —— 若会话模型被判为 DeepSeek 路由，搜索会走 legacy Messages 搜索
> （要求 `DEEPSEEK_API_KEY` 指向官方端点；走网关会失败）。
> 失败的两条回退路径：① 设置页把「网页搜索提供方」固定为 DeepSeek Search API；
> ② 在 `hostcore/profile/ondevice/cordis.patch.yml` 给 `web` 行钉回 `searchProvider: deepseek-search-api`。
> `web_fetch` 行为不变。

其中 `@deepseek-ai/*` 是 rc.4→rc.5 的定向升级，其余是 `^` 范围内的传递依赖自然漂移
