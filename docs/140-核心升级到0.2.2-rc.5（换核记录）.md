## 1.1 端侧补丁：web_search 抖动重试（`coreVersion +whale.2`）

真机实测发现 rc.5 的 `deepseek-official`（Messages 搜索）**约 2/3 成功率**：它把搜索实现为"一个带服务端
`web_search_20250305` 工具的 Messages 回合"，模型偶尔不触发工具 ⇒ 响应无 `web_search_tool_result` 块 ⇒
上游抛 `WEB_PROVIDER_ERROR` 且**不重试**；`dsh-tool-web` 的多 query 又是 **all-or-nothing**（任一失败 abort 整批），
把失败率放大到 ~30–50%。（"自动选择"与"手动选 DeepSeek 服务端搜索"走的是同一条代码路径，差别只是概率。）

⇒ 新增第 23 处端侧注入 `patchWebSearchRetry()`（`tools/pack-core.mjs`）：
把 `dsh-web-search-deepseek` 的 `async search()` 改名 `searchOnce()`，前面包一层薄 wrapper ——
**仅**对 `WEB_PROVIDER_ERROR` + message 含 `no web_search_tool_result blocks` 的错误重试，**最多 3 次尝试**（2 次重试），
`signal.aborted` 为真立即放弃。单次成功率 2/3 → ≈96%。
门禁：`check-core-openharmony-patches` 新增 ⑱ 组（标记 ×1 + 5 条正向 + 1 条反向）+ 负测试 M13；
读数 **173/0**、`--self-test` **163 用例 / 0 不合格**。

其中 `@deepseek-ai/*` 是 rc.4→rc.5 的定向升级，其余是 `^` 范围内的传递依赖自然漂移
