# 125 · 调试双包：`com.jwhsoft.whale` + 本地调试签名

> 2026-10-28 ｜ 目的：Node 24.21 / alpha.2 调试期间**不动日常包** `whale.jwh.chat` 与其数据，
> 另装一个独立包 `com.jwhsoft.whale` 做实验；稳定后再迁数据/换正式签名。
> 决策：`DECISIONS.md` D-012。

## 一、为什么换包名 + 为什么必须新建调试 Profile

- 换包名 → 系统视为**新应用**：与旧包并存、数据隔离，实验失败不影响日常 Whale。
- 但 **调试 Profile 绑定包名**（p7b 内 `bundle-info.bundle-name`）；旧 Profile 是 `whale.jwh.chat`，hvigor 会直接报
  `The bundleName in app.json5/hvigorfile.ts does not match the bundleName in the generated SigningConfigs`。
- 所以用 AGC 建了新调试 Profile（**调试类型、自动签发，无人工审核**；不是发布/ACL 申请）。

## 一·补：调试包的显示名（2026-10-29）

两个 Whale 并存时在应用列表里分不清，因此把**调试包**（`com.jwhsoft.whale`）的显示名改为 **WhaleX**，
**包名不变**（仍 `com.jwhsoft.whale`），日常包 `whale.jwh.chat` 仍显示 Whale。

改动位置：

- `AppScope/resources/base/element/string.json`：`app_name` → `WhaleX`（启动器/应用列表显示名）；
- `entry/src/main/resources/{base,en_US}/element/string.json`：`module_desc` / `EntryAbility_desc` /
  `EntryAbility_label` / `BackgroundAbility_label` / `tray_hover_tips` 里的 Whale → WhaleX（任务卡片/托盘提示）。

构建：clean 后 `sh tools/build-dev-hap.sh`；当前 HAP sha `e9185506…`，`hdc install -r` 覆盖安装即可，
数据不受影响（el2 不动）。若启动器仍显示旧名，重启应用/等启动器刷新。

## 三、构建 + 签名流程（一条命令）

```sh
cd Common/whale
sh tools/build-dev-hap.sh                     # 产物：dist/signing/dev-profile/whale-dev-latest-signed.hap
# 装：hdc install -r dist/signing/dev-profile/whale-dev-latest-signed.hap
```

脚本内部做三件事（**不要**换成直接装 hvigor 产出的 signed HAP）：
1. `devecocli build --build-mode debug`（工程里 signingConfig 是 DevEco 自动签名）；
2. 去掉签名块、**全部条目 STORED** 重打包（DEFLATE 会导致图标/资源加载不出来）；
3. 用开发者证书 `whale` + 带 ACL 的 Profile `whale-dev-debug-full` 手工重签。

已知坑：
- hvigor 自动签名生成的 Profile 是**空 ACL**，装全权限包会报 `grant request permissions failed: ACCESS_USER_FULL_DISK`；
- 首次启动（含核心重解包 + profile boot）很慢，实测 ~1–2 分钟；`NodeRuntime` 对调试包的就绪等待已从 15s 放宽到 90s；
- 调试包与日常包**同时运行**时必须错开端口：日常包 3121、调试包 **3122**（`NodeRuntime.hostPort()` 按包名决定）。

## 四、注意

1. **旧包 `whale.jwh.chat` 与它的数据不受影响**；新包首启是全新数据（会走初始化/解包，约 30s+）。
2. hvigor 的 SignHap 失败是**预期**（工程里 `signingConfigs` 仍指旧包名 Profile）；不要为此改回旧包名。
3. 用 `hdc` 抓新包日志：`hdcb shell "hilog -x | grep -iE 'com.jwhsoft.whale|dshhost|libnode|DSHM'"`（`hdcb` 包装已可用）。
4. 后续正式签名/Profile 申请沿用同一包名；正式材料到位后把 `build-profile.json5` 的 `signingConfigs` 指到正式材料即可删掉本手动签名步骤。

## 八、纠正：**不需要**带 ACL 的调试 Profile（2026-11-03 实测）

之前用 AGC 的「带 4 项 ACL 的调试 Profile」（`whale-dev-debug-full`）签全功能包，结果 **2026-11-02 20:54 过期**，
应用弹「应用已过期，无法继续使用」。原因：**AGC 对带受限权限的调试 Profile 只签发 5–7 天**。
于是做了一次 A/B 对照（同一个 HAP，只换 Profile，用 `atm dump -t -b com.jwhsoft.whale` 读 token 权限状态）：

| 权限 | 无 ACL Profile | 带 ACL Profile |
|---|---|---|
| `ALLOW_EXTERNAL_NATIVE_CODE` | grantStatus **0（已授予）** | 0 |
| `CUSTOM_SANDBOX` | 0 | 0 |
| `READ_WRITE_USER_FILE` | 0 | 0 |
| `ACCESS_USER_FULL_DISK` | **-1** | **-1** |
| 其余（INTERNET / FILE_ACCESS_PERSIST / …） | 0 | 0 |

结论：

1. **ACL Profile 没有带来任何额外权限**——三项关键 ACL 在无 ACL 的 Profile 下同样是「已授予」；
2. `ACCESS_USER_FULL_DISK` 在本机（HarmonyOS 7.0.0.105）**系统里没有这个权限定义**（`atm perm -g` 直接报
   `Permission 'ohos.permission.ACCESS_USER_FULL_DISK' does not exist`），带不带 ACL 都是 `-1`；
   之前看到的「`grant request permissions failed: ACCESS_USER_FULL_DISK`」不是缺 ACL，而是这条权限本身在本机无效；
3. ⇒ **签名一律用 `whale-dev-debug.p7b`（无 ACL，365 天）**，不用再 5 天续签；
   `tools/build-dev-hap.sh` / `tools/sign-dev-hap.sh` 的默认 Profile 已改为它。
4. 带 ACL 的旧 Profile 文件保留为 `.expired-<日期>` 备份，仅供回查。
