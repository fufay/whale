## 一、为什么做

DSH `0.2.2-alpha.2`（含"系统提示词未变时复用上下文前缀缓存"的省 token 修复）要求 `engines.node >= 24.9.0`；
Whale 现网内嵌 Node 是 **24.2.0**。Node 24.21.0 已在本机原生构建成功（ABI 仍为 24 线 **modules=137**），
先做 **Phase 0：只换 Node、dsh 仍保持 `0.2.1-rc.2+whale.2`**，把变量隔离。

## 五、坑（本次新踩，后续别再踩）

1. **`bash` 不是真 bash**：本机 `bash` 是鲸鱼垫片（→ `/system/bin/sh`），`sync-node-headers.sh` 里的 `${BASH_SOURCE[0]}` 会报 `bad substitution`。
   必须用真 bash：`/storage/Users/currentUser/.harmonybrew/bin/bash tools/node-runtime/sync-node-headers.sh <node 源码树>`（该脚本参数是 **Node 源码树**，不是 `install/include/node`）。
2. **hvigor 不会因 `node-headers/` 变化而重编 native**：换了头文件后普通 build 只重打包（`libdshhost.so` mtime 仍是旧的），必须先删
   `entry/build/default/intermediates/cmake` 与 `entry/.cxx` 再 build（本次已踩）。
3. **HAP 打包会去掉内嵌 .so 的 `.codesign`**：源产物有有效自签，包内没有；这与 docs/50 E18 一致，dlopen 不需要它，**不要**为此再加签名步骤。
4. 新版 libnode 是 llvm@22 构建（含静态 libc++/libunwind，NEEDED 只有 `libc.so`）；`libdshhost.so` 仍按 `-fno-emulated-tls -D__MUSL__` 口径编译，与 docs/50 §4.2 一致。
